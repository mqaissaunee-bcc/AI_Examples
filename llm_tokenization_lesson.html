What are tokens?

Tokens are the units a large language model reads and writes. A token is often a whole word, but it can also be part of a word, a punctuation mark, or a space plus a word.

Library analogy

If a document is a book, tokens are its pages. A librarian works through a book page by page; a model works through text token by token.

What becomes a token

  • Whole words: "hello", "world"
  • Word pieces: "un", "ing", "tion"
  • Punctuation: ".", "!", "?"
  • Numbers and symbols: "@", "#", "2026"

Rules of thumb (English)

  • 1 token is about 4 characters
  • 1 token is about three-quarters of a word
  • 1,000 tokens is about 750 words
  • Other languages have different ratios

Byte pair encoding in one paragraph

Most tokenizers start from single characters and repeatedly merge the pairs that appear together most often. If "ing" is common, it becomes one token instead of three letters. Common words end up as single tokens; rare words are spelled out in pieces.

Context windows

The context window is the model's working memory: the most tokens it can consider at once, counting your prompt, any attached documents, the conversation so far, and its own reply.

Conversation analogy

You remember the last few minutes of a conversation clearly and the first hour only vaguely. A model has a hard version of that limit: anything outside the window is not there at all.

Pricing and costs

When you use a model through its API, you pay per token, with one rate for input (what you send) and a higher rate for output (what it writes). Chat subscriptions hide this, but the same metering sits underneath.

Utility bill analogy

You pay for electricity by the kilowatt-hour. You pay for a model by the token. Prices are quoted per million tokens.

Why output costs more

Reading is one pass over text that already exists. Writing means producing new text one token at a time, each token depending on everything before it. On every model in the table above, an output token costs five times as much as an input token.

Going deeper

Other languages

Token counts depend on the language. Text in languages that are less common in the training data, or that use long compound words, usually takes more tokens for the same meaning.

Prompt caching

If you send the same long instructions or document again and again, providers can cache it. Cached input is billed at a small fraction of the normal rate.

Batch processing

Work that can wait can be sent as a batch. OpenAI, Anthropic and Google all list batch rates at half the standard price.

Thinking tokens

Many current models work through a problem before answering. That hidden reasoning is billed as output tokens, so a hard question can cost far more than its short answer suggests.

Long-prompt surcharges

A large context window does not always come at one price.

The intake desk

Think of a tokenizer as a factory's intake desk. It breaks incoming material into standard units the machines can handle. Different factories use different unit sizes, which is why the same sentence has a different token count on different models.

In practice

Most of the skill is matching the size of the model to the size of the job.

Ways to spend less

Ask for less

Output is the expensive side. "Summarize the key findings in three bullet points" costs less than "tell me everything about this document".

Use the smallest model that works

Batch what can wait

Half price for work that does not need an immediate answer.

Cache what repeats

A long system prompt or reference document sent with every request is the ideal thing to cache.
