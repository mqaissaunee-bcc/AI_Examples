Add live, shared data to a static website with Firebase

Make a web page where many people’s phones and laptops share the same data in real time: votes, poll answers, game rounds, sign-ups. No server to run, no cost for classroom-sized use. This guide uses a real classroom game as its worked example, but the steps work for any project.

What Firebase is

Firebase is Google’s set of ready-made tools for building apps and websites. You use the pieces you need and skip the rest. This guide uses two of them:

  • Realtime Database. A database in the cloud that your web page reads and writes directly. When one person’s page changes something, every other open page sees the change within about a second, without anyone reloading.
  • Authentication. A way to know which device is which. We use its anonymous option: each visitor gets a random ID automatically, with no name, email, or password.

Firebase also does hosting, file storage, and more, but you don’t need any of that here. Your page can stay wherever it already lives, such as GitHub Pages or a college web server.

When you need it

Most course tools built as a single HTML file run entirely inside each person’s browser. That’s great until you want people to share something. A static page has no way to collect what 30 phones are doing, because there’s nowhere for that information to go. Firebase is the place it goes.

Good fitNot a good fit
Live polls, votes, and quizzes during class or a workshopGrades, student records, or anything covered by FERPA
Classroom games where phones follow the projectorNames, emails, ID numbers, or other personal information
Anonymous question boards and word cloudsAnything that needs a real login with your college account
Sign-up sheets or shared checklists with first names onlyLarge files, videos, or long-term archives

Why not something simpler?

We tried a simpler route first, and it’s worth knowing why it didn’t hold up. Free public “relay” services can pass messages between browsers with no setup at all. They work well for one or two people. But they limit traffic per internet address, and on campus Wi-Fi a whole room usually shares one address. In a room of 30, phones started hitting those limits, and there was no room left for sending votes. Firebase counts each device separately, so the size of the room doesn’t matter.

Free plan limits

The free plan, called Spark, needs no credit card and can’t charge you. For classroom tools, the limit that matters is 100 devices connected at once per database. It also includes 1 GB of stored data and 10 GB of downloads a month, far more than votes or poll answers will use. If you ever reach a limit, Firebase stops accepting new connections until usage drops. Nothing is billed.

The sample project: AI or Faculty?

This guide follows a real example from the Fall 2026 AI Teaching Workshop Series. AI or Faculty? is an icebreaker where each round shows a short piece of teaching writing, and players guess whether a colleague or AI wrote it.

  • The facilitator runs the game on a projector. Players join from their phones with a game code.
  • When the facilitator reveals an answer or moves to the next round, every phone follows.
  • Each phone’s vote is counted on the projector as it comes in, and the results can be downloaded as a spreadsheet.

Throughout the steps, boxes labeled In the sample project show exactly what was done for this game. Everything else applies to any project. The sample uses a project named ai-or-faculty; wherever you see that, use your own project’s name.

Key ideas before you start

TermWhat it means
ProjectA container in Firebase for one app or tool. One project can serve several related pages.
PathThe database is one big tree of data, like folders. A path such as games/4821/votes points to one branch of it.
Security rulesA short set of instructions stored in Firebase that decides who can read and write each path. Your rules, not secrecy, are what protect your data.
ConfigA small block of settings that tells your page which project to talk to. It’s meant to be public and safe to put in a web page.
Authorized domainA website address you’ve told Firebase to accept sign-ins from, such as yourname.github.io.

Step 1Create a Firebase project

  1. Go to console.firebase.google.com and sign in with a Google account. Your college doesn’t need to be a Google school; a personal account works. See Privacy and upkeep before picking which account.
  2. Click Create a project (on some screens, Get started by setting up a Firebase project).
  3. Type a project name. Firebase turns it into a project ID. If the name is already taken by someone else, it adds random characters, like my-poll-4f7c2. Either way is fine. Note the ID it shows; you’ll see it again.
  4. Accept the terms and continue.
  5. When asked about Google Analytics, turn it off. You don’t need it, and it means less data collected about your users.
  6. If it asks about Gemini or AI assistance in Firebase, either choice is fine.
  7. Click Create project, wait, then click Continue.

In the sample project: the name ai-or-faculty was available, so the project ID came out exactly ai-or-faculty with no extra characters.

Step 2Turn on anonymous sign-in

Anonymous sign-in gives every device a random ID the moment the page opens. Your rules can then say things like “each device may only change its own vote,” without asking anyone to create an account.

Finding Authentication: it is not in the gear-icon menu (that menu only has project settings like General, Usage and billing, and Integrations). The quickest way to get there is the search box at the top of the console: type Authentication and choose it. You can also expand the left menu, which may be collapsed to icons, and look under Security or Build.

  1. Open Authentication using the search box.
  2. Click Get started.
  3. Open the Sign-in method tab.
  4. In the list of providers, click Anonymous.
  5. Turn on Enable, then click Save.

Anonymous should now show as Enabled. You don’t need any other provider.

Step 3Create the database

  1. Search for Realtime Database in the box at the top of the console and open it. Make sure it says Realtime Database, not Firestore, which is a different Firebase database.
  2. Click Create Database.
  3. Choose a location. United States (us-central1) is a good default in the U.S.
  4. Choose Start in locked mode. Locked means nobody can read or write anything until you add rules in the next step. That’s the safe starting point.
  5. Click Enable.

You’ll land on the Data tab. At the top is your database URL, which looks like https://your-project-id-default-rtdb.firebaseio.com. If you chose a location outside us-central1, it ends in firebasedatabase.app instead.

Quick check: paste your database URL into a browser and add /.json to the end. A message saying Permission denied is exactly what you want: the database exists and it’s locked.

Step 4Write your security rules

Rules are the most important part of the setup. Your page’s code runs on other people’s devices, so anyone could edit it. Rules are enforced by Firebase itself, so they protect your data no matter what code someone runs.

How rules read

  • ".read" and ".write" say who can read or change a path. auth != null means “any signed-in device,” and auth.uid === $uid means “only the device whose ID matches this spot.”
  • ".validate" says what the data must look like, such as a number, a short piece of text, or one of a few allowed words.
  • A name starting with $, like $uid, is a placeholder that matches any key at that level.
  • Start from false at the top and open up only the paths your page uses.

Apply your rules

  1. In Realtime Database, open the Rules tab.
  2. Select everything in the editor and delete it.
  3. Click Copy on one of the rule sets below and paste it in.
  4. Click Publish.

Starter rules for a poll or response board

Use these for a simple project where each visitor submits one answer and everyone can see all answers. Each device can only write its own entry, and each entry must be a short answer plus a time. Pair them with the example code in step 7.

{
  "rules": {
    ".read": false,
    ".write": false,
    "responses": {
      ".read": "auth != null",
      "$uid": {
        ".write": "auth != null && auth.uid === $uid",
        ".validate": "newData.hasChildren(['answer', 'time'])",
        "answer": { ".validate": "newData.isString() && newData.val().length <= 200" },
        "time": { ".validate": "newData.isNumber() && newData.val() <= now" },
        "$other": { ".validate": false }
      }
    }
  }
}
In the sample project: the rules for AI or Faculty?

The game needs more control: one device (the projector) owns each game, phones may only cast their own vote, and voting closes 24 hours after a game starts. Under games/code it stores an owner ID, a start time, the current round, and the votes. These are a good model for any project with one “host” device and many participants.

{
  "rules": {
    ".read": false,
    ".write": false,
    "games": {
      "$code": {
        ".read": "auth != null",
        ".write": "auth != null && (!data.exists() || data.child('owner').val() === auth.uid)",
        ".validate": "$code.matches(/^[0-9]{4,5}$/) && newData.child('owner').isString() && newData.child('created').isNumber()",
        "owner": {
          ".validate": "newData.isString() && (data.exists() ? newData.val() === data.val() : newData.val() === auth.uid)"
        },
        "created": {
          ".validate": "newData.isNumber() && (data.exists() ? newData.val() === data.val() : newData.val() <= now)"
        },
        "state": {
          ".validate": "newData.hasChildren(['i', 'n', 'r'])",
          "i": { ".validate": "newData.isNumber() && newData.val() >= 0 && newData.val() <= 100" },
          "n": { ".validate": "newData.isNumber() && newData.val() >= 1 && newData.val() <= 100" },
          "r": { ".validate": "newData.isBoolean()" },
          "$other": { ".validate": false }
        },
        "votes": {
          "$round": {
            ".validate": "$round.matches(/^[0-9]{1,3}$/)",
            "$uid": {
              ".write": "auth != null && auth.uid === $uid && root.child('games/' + $code + '/created').val() > now - 86400000",
              ".validate": "newData.val() === 'ai' || newData.val() === 'faculty'"
            }
          }
        },
        "$other": { ".validate": false }
      }
    }
  }
}

In plain terms: nothing outside games is reachable. Anyone signed in can start a game with an unused code; after that, only the device that started it can change rounds, clear votes, or delete it. Each phone can write only its own vote, only “ai” or “faculty,” and only within 24 hours.

If Publish shows an error, a bracket was probably lost when pasting. Select all, delete, and paste again using the Copy button.

Step 5Register a web app and get your settings

This creates the config: the block of settings your page uses to find your project.

  1. Click the gear icon next to Project Overview, then Project settings.
  2. On the General tab, scroll to Your apps and click the web icon, </>.
  3. Give the app a nickname, such as the name of your tool.
  4. Leave Also set up Firebase Hosting unchecked unless you want Firebase to host the page too.
  5. Click Register app, then Continue to console. You can skip the rest of Firebase’s setup instructions.

Copy your real config

Back on Project settings → General, scroll to your app under Your apps. Under SDK setup and configuration, choose Config. You’ll see a block shaped like this one, with your own values:

const firebaseConfig = {
  apiKey: "AIzaSy...about 39 characters...",
  authDomain: "your-project-id.firebaseapp.com",
  databaseURL: "https://your-project-id-default-rtdb.firebaseio.com",
  projectId: "your-project-id",
  storageBucket: "your-project-id.firebasestorage.app",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:..."
};

Copy it from Firebase, not from this page. The block above, and any example you see in a tutorial, is only a shape. If your config contains your-project-id, dots like AIzaSy..., or another project’s name, the page won’t connect.

Check for databaseURL. If your block has no databaseURL line, add one using the database URL from the top of the Realtime Database Data tab, in quotes with a comma after it.

Is it safe to publish this? Yes. Despite its name, the apiKey isn’t a password. It only identifies your project, and Firebase expects it to be visible in web pages. Your security rules are what protect the data.

Step 6Allow your website

Firebase only accepts sign-ins from websites you list.

  1. Search for Authentication again and open its Settings tab.
  2. Click Authorized domains, then Add domain.
  3. Enter just the site’s domain: no https://, no slashes, no page names. For GitHub Pages that’s yourname.github.io, even if your page is in a folder like yourname.github.io/course/.
  4. Click Add.

localhost is usually already on the list, which lets you test on your own computer.

In the sample project: the game lives at mqaissaunee-bcc.github.io/fall26-ai/, so the authorized domain is mqaissaunee-bcc.github.io.

Step 7Connect your page

Your page needs three things: Firebase’s code libraries, your config, and a few lines that sign in and read or write data.

A minimal working example

This matches the starter rules from step 4. It signs each visitor in anonymously, saves their answer, and shows everyone’s answers live. Paste it near the end of your page’s <body> and replace the config with yours.

<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-app-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-auth-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-database-compat.js"></script>
<script>
  // 1. Your settings from step 5
  const firebaseConfig = {
    apiKey: "...",
    authDomain: "your-project-id.firebaseapp.com",
    databaseURL: "https://your-project-id-default-rtdb.firebaseio.com",
    projectId: "your-project-id",
    appId: "..."
  };
  firebase.initializeApp(firebaseConfig);
  const db = firebase.database();

  // 2. Give this device a random ID, then use the database
  firebase.auth().signInAnonymously().then(({ user }) => {

    // Save this visitor's answer (each device can only write its own)
    function sendAnswer(text) {
      db.ref("responses/" + user.uid).set({
        answer: text,
        time: firebase.database.ServerValue.TIMESTAMP
      });
    }
    sendAnswer("Hello from " + navigator.platform);

    // Show everyone's answers, updating live
    db.ref("responses").on("value", snapshot => {
      const all = snapshot.val() || {};
      console.log(Object.keys(all).length + " answers:", all);
    });

  }).catch(err => console.error("Firebase sign-in failed:", err.code));
</script>

Open the page in two browser windows and check the console (F12, then Console). Both windows should list both answers.

In the sample project: the game already contains all the Firebase code. It has one line near the top of its script, const FIREBASE_CONFIG = null;. Setup meant replacing null with only the part of the config from { to }, leaving out Firebase’s const firebaseConfig =, because the game already has its own name for it. While the value is null, the game falls back to counting votes by hand, so it still works before setup is done.

Paste once. A common mistake is pasting Firebase’s whole block, including const firebaseConfig =, into a line that already starts with const. You end up with two consts and the page stops working. Check that the finished line has one const and ends with };.

Step 8Test it

  1. Upload your page. On GitHub Pages, wait a minute or two for it to update.
  2. Open it on two devices, such as a laptop and a phone, and do whatever the page does: vote, answer, join.
  3. Check that what you do on one device shows up on the other within a second or two.
  4. In the Firebase console, open Realtime Database → Data. You should see your data appear in the tree as you use the page.
  5. Test once more on the network you’ll actually use, such as campus Wi-Fi in the room where you’ll teach. Some networks block certain services.

Optional: test your rules

On the Rules tab, the Rules Playground lets you try a pretend read or write and see whether your rules allow it. Try something that should be refused, such as writing to another device’s spot or writing a value your rules don’t allow, and confirm it’s denied.

In the sample project: testing confirmed anonymous sign-in worked, a game could be created, a valid vote was accepted, a made-up vote value was refused, and reading without signing in was refused. Every test sign-in leaves an anonymous user in Authentication → Users. That’s harmless, and you can delete them.

Optional: build a new page with an AI assistant

Setup is complete after step 8. This section is for later, when you want a new tool that uses your Firebase project, such as a live poll or a question board. You don’t need it for the sample game, which already has its Firebase code.

An AI assistant can write the page for you. Give it your config and your rules so the code it writes actually matches your database. A prompt that works well:

Build a single self-contained HTML page for [describe your tool, e.g. a live
class poll where students pick A, B, C, or D and the projector shows a bar chart].

Use Firebase Realtime Database with the compat SDK from
https://www.gstatic.com/firebasejs/10.12.2/ (app, auth, database) and anonymous
sign-in. Here is my config:
[paste your config]

These are my security rules. The page must only read and write data in exactly
this shape:
[paste your rules]

Don't collect names or any personal information. Show a clear message if
Firebase can't connect, and keep the page usable without it if possible.

If you change what the page stores, change the rules to match. Ask the assistant to update both together.

Privacy and upkeep

  • Store as little as possible. Anonymous IDs and answers are enough for most classroom tools. Don’t store student names, emails, ID numbers, or grades, and follow your institution’s policies on student data.
  • Choose the account carefully. The project belongs to whichever Google account creates it. If a tool will be used by a department for years, consider a shared departmental account, or add a colleague as a second owner under the gear icon → Users and permissions, so the project isn’t lost if you leave.
  • Clean up. Delete old data from the Data tab: hover over a branch, open its three-dot menu, and choose Delete. Your rules and settings stay, so the page keeps working. The sample game deletes each game’s data automatically when the facilitator starts a new one.
  • One project, several tools. You can reuse a project for related tools by giving each its own top-level path, like games and polls, each with its own rules.

Troubleshooting

I can’t find Authentication or Realtime Database

They aren’t in the gear-icon menu. Use the search box at the top of the console, or go straight to them by address, replacing your-project-id with your project ID (shown under Project settings → General):

https://console.firebase.google.com/project/your-project-id/authentication
https://console.firebase.google.com/project/your-project-id/database

An error mentions “operation-not-allowed” or “admin-restricted-operation”

Anonymous sign-in isn’t turned on. Go back to step 2.

An error mentions “unauthorized-domain”

Your website isn’t on the authorized domains list, or it’s entered with https:// or a folder name. Go back to step 6.

An error mentions “invalid-api-key” or the page never connects

The config is probably an example rather than your own. Copy it again from Project settings → General → Your apps → Config (step 5).

An error says “permission denied”

Your rules refused the read or write. Either the rules didn’t publish, or the page is writing to a path or in a shape the rules don’t allow. Compare the path and data in your code with your rules, and try the write in the Rules Playground.

Nothing happens, and there’s no error

Usually the databaseURL line is missing or wrong. Compare it with the address at the top of the Realtime Database Data tab, including whether it ends in firebaseio.com or firebasedatabase.app.

The page stopped working after I pasted the config

Look for a doubled const, a missing comma between lines, or a missing }; at the end. Your browser’s console (F12) shows the line with the problem.

It works at home but not on campus

The network may be blocking Firebase. Ask IT to allow *.firebaseio.com, *.firebasedatabase.app, and identitytoolkit.googleapis.com, or have people use cellular data.

Some devices can’t connect in a very large group

The free plan allows 100 devices connected to one database at a time. For bigger groups, plan a way for extra people to take part without connecting, such as a show of hands.
